# Clear one injected database fault
An alert can propose clearing the active PayFlow database fault. Its generation UUID changes on each injection. A row-locked operator decision and audit entry commit before dispatch. PayFlow accepts only the matching active generation on a fixed internal endpoint. It never runs shell commands. The executor credential grants this single operation and read-only verification. Keep internal routes behind private ingress. Existing operator controls remain available for manual simulation setup and cleanup.

Verification requires three successful database readiness and fault-state observations spaced two seconds apart. The action outcome records recovered, persisted (a fault remains), or failed (dispatch or verification failed). Alertmanager resolution time is a separate observation. If a process crashes after dispatch, the action can remain executing. Inspect the audit and fault state before manual intervention. The system deliberately does not replay uncertain actions. PayFlow's generation and fault state belong to a single simulation process.
